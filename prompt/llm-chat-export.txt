➡️ Used when form is NOT directly linked to a model.

➡️ Used when form is directly linked to a database model.

Here is the simplest and most practical explanation of when to use which type of Django form, with real-world examples.

✅ Django Forms — Which one to use when?
There are two types:

forms.Form

forms.ModelForm

Think of them like this:

🟦 1) Use forms.Form when your form is NOT directly saving data to a model.
This is for “random input forms” → simple, temporary, one-time forms.

✔️ Use it when:
You just want to collect some input (not store in DB).

You want custom fields that are not in any model.

You need only validation, no saving.

You want full control over fields.

✔️ Real-life examples:
Example	Why use forms.Form?
Contact Us form	You want to send email, not save to DB.
Search bar	Searching does not need DB saving.
Login form	You check credentials, you don’t save login info.
Feedback form (only email notification)	Only sending emails, not storing.
Two-number calculator (sum)	No DB involved.
✔️ Small Example:
class LoginForm(forms.Form):
    username = forms.CharField()
    password = forms.CharField(widget=forms.PasswordInput)
🟩 2) Use forms.ModelForm when your form data MUST be saved to a database model.
This is used for CRUD (Create, Read, Update, Delete) operations.

✔️ Use it when:
You want to save form data in a model.

Form fields match model fields.

You want Django to automatically do validation based on model.

You want to create/edit records easily.

✔️ Real-life examples:
Example	Why use ModelForm?
User Registration (saving new user)	Data goes into User model.
Add a new Product	Product model.
Create Blog Post	BlogPost model.
Create/Edit Student data	Student model.
Upload Image/File	FileMixin + Model saves files.
Employee form (storing in DB)	Employee model.
✔️ Small Example:
class StudentForm(forms.ModelForm):
    class Meta:
        model = Student
        fields = ['name', 'age', 'email']
🧠 How to decide instantly? (Simple Rule)
If your form's goal is to STORE data → use ModelForm.
If your form's goal is ONLY to TAKE input temporarily → use Form.
🟨 Visual Cheat Sheet (easy to remember)
Task	Use Which Form?
Contact Us form	forms.Form
Search box	forms.Form
Login form	forms.Form
Sign-up (save user)	forms.ModelForm
Create blog post	forms.ModelForm
Edit blog post	forms.ModelForm
Add student record	forms.ModelForm
Update employee record	forms.ModelForm
Upload image to DB	forms.ModelForm
A calculator page	forms.Form
Feedback (save feedback in DB)	forms.ModelForm
🧩 What if I need some fields from model + some custom fields?
Use ModelForm, then add custom fields:

class ProductForm(forms.ModelForm):
    extra_note = forms.CharField(required=False)

    class Meta:
        model = Product
        fields = ['name', 'price', 'description']
⭐ Summary (One Line Rule)
Use ModelForm whenever you want to save/update data in the database.
Use Form when you just want to collect or process input temporarily.

Minimal models (example) — models.py
from django.db import models
from django.conf import settings

class Reward(models.Model):
    title = models.CharField(max_length=120)
    description = models.TextField(blank=True, null=True)
    cost = models.PositiveIntegerField(default=0)
    image_url = models.URLField(blank=True, null=True)
    in_stock = models.BooleanField(default=True)

    def __str__(self):
        return self.title

class Redemption(models.Model):
    user = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    reward = models.ForeignKey(Reward, on_delete=models.PROTECT)
    points_used = models.PositiveIntegerField()
    created_at = models.DateTimeField(auto_now_add=True)
    STATUS_CHOICES = [('pending','Pending'), ('done','Done'), ('cancelled','Cancelled')]
    status = models.CharField(max_length=20, choices=STATUS_CHOICES, default='pending')

    def __str__(self):
        return f"{self.user} - {self.reward} ({self.points_used})"

View example — views.py
from django.shortcuts import render, redirect, get_object_or_404
from django.contrib.auth.decorators import login_required
from django.utils import timezone
from .models import Reward, Redemption
from .forms import RedemptionForm
from django.contrib import messages

@login_required
def redemption_page(request):
    # get user points from your profile model or calculate
    user_points = request.user.profile.points   # adapt to your model
    rewards = Reward.objects.filter(in_stock=True).order_by('cost')
    history = Redemption.objects.filter(user=request.user).order_by('-created_at')[:10]

    return render(request, 'redemption.html', {
        'user_points': user_points,
        'available_points': user_points,
        'rewards': rewards,
        'redemption_history': history,
    })

@login_required
def redeem(request, reward_id=None):
    # If using direct POST form (action -> redeem view)
    if request.method != "POST":
        return redirect('redemption_page')

    # get reward id either from URL or POST
    rid = reward_id or request.POST.get('reward_id')
    reward = get_object_or_404(Reward, id=rid)

    # check points & stock
    user_points = request.user.profile.points
    if not reward.in_stock:
        messages.error(request, "Reward out of stock.")
        return redirect('redemption_page')

    if user_points < reward.cost:
        messages.error(request, "Not enough points to redeem this reward.")
        return redirect('redemption_page')

    # create redemption, deduct points (wrap in transaction in real app)
    Redemption.objects.create(
        user=request.user,
        reward=reward,
        points_used=reward.cost,
        created_at=timezone.now(),
        status='pending'
    )

    # deduct points from user profile
    request.user.profile.points -= reward.cost
    request.user.profile.save()

    messages.success(request, f"You have redeemed {reward.title} for {reward.cost} points!")
    return redirect('redemption_page')

Notes & quick tips
Replace request.user.profile.points with however you store user points (e.g., Profile model).

Wrap the redeem logic in a DB transaction to avoid race conditions if many users redeem the same reward.

Validate server-side (always) — don't rely on disabled buttons client-side.

For immediate UX, you can use AJAX to submit redemption and update points live.

Add admin pages to manage rewards and mark in_stock = False when exhausted.
